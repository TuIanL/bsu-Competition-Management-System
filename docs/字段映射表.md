## 1. volunteer（志愿者）

| 页面/接口字段 | 类型 | 数据库字段 | 约束 | 备注 |
|---|---|---|---|---|
| id | Integer | volunteer.id | PK | 只读 |
| student_no | String | volunteer.student_no | UNIQUE, 非空 | 新增必填；**同时也是志愿者端登录账号** |
| name | String | volunteer.name | 非空 | |
| phone | String | volunteer.phone | 可空 | |
| skill | String | volunteer.skill | 可空 | 如：急救、检票 |
| status | Enum | volunteer.status | CHECK | `ACTIVE`/`INACTIVE` |
| password_hash | — | volunteer.password_hash | **NOT NULL** | 初始密码=学号后六位（seed 用 sha256）；登录后提示修改；接口不返回该字段。⚠️ 新增志愿者时后端**必须**生成初始密码，否则违反 NOT NULL |

## 5. assignment（调度 · 核心）

| 页面/接口字段 | 类型 | 数据库字段 | 约束 | 备注 |

## 7. 统计量（数据来源，与仓库 schema V1.2 对齐）

> 仓库 schema V1.2 **只建了 1 个视图 `v_shift_status`**；其余统计由 `database/core_queries.sql` 的查询提供。
> 如后续确需 `v_shift_roster` / `v_volunteer_stats` 视图，须由张照锐改动 schema（并知会全组）。

| 页面显示 | 来源 | 计算 |
|---|---|---|
| 已安排人数 | `v_shift_status.assigned_count` | COUNT(status IN ASSIGNED, COMPLETED) |
| 剩余缺口 | `v_shift_status.remaining_count` | required_count − assigned_count |
| 是否满员 | **前端/后端判断** | `remaining_count <= 0`（V1.2 无 is_full 字段） |
| 班次名单（已排班） | `core_queries.sql ⑦` | assignment JOIN volunteer；排除 CANCELLED |
| 报名候选人 | `core_queries.sql ①` | application JOIN volunteer；不是已排班名单 |
| 我的班次 | `core_queries.sql ②` | assignment JOIN shift/event/role |
| 志愿时长(分钟) | `core_queries.sql ③` | SUM((julianday(check_out)−julianday(check_in))×1440)，status=COMPLETED |
| 可报名班次 | `core_queries.sql ④` | 未来班次 + 未结束赛事 + 剩余名额 > 0 |
| 缺口排行(Dashboard) | `core_queries.sql ⑤` / v_shift_status | ORDER BY remaining_count DESC LIMIT 10 |
