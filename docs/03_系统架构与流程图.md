## 1. 总体架构图

数据流向：**微信小程序（双端）→ Flask JSON API（Session 鉴权 + 角色分流）→ sqlite3 → SQLite**。

```mermaid
flowchart LR
    subgraph 前端["微信小程序 · 双端"]
        MA[管理端页面组<br/>login/dashboard/volunteers<br/>events/shifts/schedule]
        VO[志愿者端页面组<br/>my-schedule/positions/my-hours]
    end
    subgraph 后端["Flask JSON API"]
        LG[统一登录 /api/login<br/>按 role 分流]
        AU[鉴权 + 角色校验<br/>admin / volunteer]
        BL[业务校验层<br/>R1-R8]
    end
    subgraph 数据层["SQLite"]
        DB[(database/schema.sql V1.2<br/>7 表 + 1 视图 v_shift_status<br/>+ 6 索引)]
    end
    MA -- "wx.request JSON" --> LG
    VO -- "wx.request JSON" --> LG
    LG --> AU --> BL
    BL -- "参数化 SQL" --> DB
    DB -- 结果 --> BL --> MA
    BL --> VO
```

## 3. 管理端调度业务流程图（Assignment 闭环）

```mermaid
flowchart TD
    Start[管理员登录] --> Maint[维护基础数据<br/>志愿者/赛事/岗位/班次]
    Maint --> Sel[选择班次 + 志愿者<br/>可参考报名列表 P1]
    Sel --> C1{R1 志愿者 ACTIVE?}
    C1 -- 否 --> E1[拒绝：已停用]
    C1 -- 是 --> C2{R2 同人同班次已存在?}
    C2 -- 是 --> E2[拒绝：重复调度]
    C2 -- 否 --> C3{R3 时间重叠?}
    C3 -- 是 --> E3[拒绝：时间冲突]
    C3 -- 否 --> C4{R4 已满员?}
    C4 -- 是 --> E4[拒绝：满员]
    C4 -- 否 --> W[(写入 assignment<br/>status=ASSIGNED)]
    W --> U[更新名单/缺口统计 v_shift_status]
    U --> Done[调度成功]
```

## 4. 志愿者端业务流程图（v2 新增）

```mermaid
    CKIN --> CJ{班次结束?}

    CKOUT --> MH[我的志愿时长<br/>Σ check_out−check_in]
```

## 6. 数据库课程重点速查（答辩用）

| 知识点 | 本项目落点 |
|---|---|
| 主键 PK / 外键 FK | 7 张表均 INTEGER PK；shift/assignment/application 含 FK |
| UNIQUE | student_no、role.name、UNIQUE(shift_id,volunteer_id)、UNIQUE(volunteer_id,shift_id) |
| CHECK | status 枚举（含 assignment 的 COMPLETED）、start<end、required_count>0、check_out_at>=check_in_at、COMPLETED 必须有签到签退时间 |
| JOIN | assignment/application 关联 volunteer/shift/event/role |
| 聚合 GROUP BY | v_shift_status；core_queries.sql 的时长/可报名聚合 |
| 视图 | v_shift_status（V1.2 唯一视图，含缺口统计） |
| 索引 | 6 个 idx_（含 idx_shift_time 复合索引） |
| 参数化 SQL | 所有接口 ? 占位符 |
| 双端会话 | session.role 分流，越权 403 |
