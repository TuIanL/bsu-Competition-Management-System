# 01 项目范围说明（冻结版 · 双端）

> 文档归属：刘腾罡（项目管理员 + 系统分析员）｜版本：V2 冻结｜2026-10-02
> 作用：本文件是四个人使用 AI 时的"系统边界"。范围未冻结前，任何人不得大规模开始开发。
> 配套事实源：database/schema.sql V1.2、docs/api-contract.md v2（联调草案）、docs/字段映射表.md
> v2 变更：由"仅管理员端"升级为**管理端 + 志愿者端双端**（来源：@zzy 双端小程序实施方案）。

## 1. 项目最终定义

| 项 | 定义 |
|---|---|
| 最终名称 | 体育赛事志愿者调度系统 · 双端小程序 |
| 交付形式 | 单个小程序双端（管理端 + 志愿者端）+ Flask JSON API + SQLite + 微信开发者工具演示 |
| 用户角色 | **管理员**（管理端）、**志愿者**（志愿者端）；共用 `/api/login`，按返回的 `role` 分流 |
| 技术路线 | 微信小程序前端 → Flask JSON API / Session → sqlite3 → SQLite（**不引入微信云开发**，关系型约束是课程重点） |
| 核心业务 | 管理员维护志愿者/赛事/岗位/班次并执行 Assignment 调度；志愿者自主查看班次、报名岗位、签到签退、查看志愿时长 |
| 产品主线 | 所有设计回答"对赛事组委会有什么用"：调度闭环、报名候选参考、运营驾驶舱（阶段二） |

> 关键定位：**报名意向由志愿者提交，最终排班动作仍由管理员确认执行**。冲突/满员等规则只在管理员分配时触发一次，不拆两套逻辑。

## 2. P0 功能清单（必须全部通过，否则阻塞交付）

### 管理端

| 编号 | 功能 | 验收 |
|---|---|---|
| P0-1 | 管理员登录 | 正确账号成功，错误密码有提示 |
| P0-2 | 志愿者 CRUD | 新增/编辑/停用/查询，学号唯一 |
| P0-3 | 赛事、岗位管理 | 新增/编辑，字段与后端一致 |
| P0-4 | 班次管理 | 开始/结束时间合法性校验 |
| P0-5 | 调度（管理员手动分配） | 重复分配/时间冲突/满员三类拒绝均有明确提示 |
| P0-6 | 取消调度 | 已安排记录可取消/更新状态（保留历史） |
| P0-7 | 班次名单与缺口统计 | assigned_count / remaining_count 随调度变化，实时刷新 |
| P0-8 | Dashboard 统计 | 数字来自真实接口 |

### 志愿者端

| 编号 | 功能 | 验收 |
|---|---|---|
| P0-9 | 志愿者登录 | 学号+密码登录，与管理员共用同一登录接口，按 role 跳转 |
| P0-10 | 我的班次 | 展示已被分配的全部班次及状态 |
| P0-11 | 可报名班次浏览 | 展示未来且有剩余名额、所属赛事未结束的班次 |
| P0-12 | 提交报名 | 同一岗位不能重复报名 |
| P0-13 | 签到/签退 | 记录 check_in_at/check_out_at，均不做 GPS/人脸识别 |
| P0-14 | 我的志愿时长 | 按（check_out_at − check_in_at）实际时长自动累加 |

### 通用

| 编号 | 功能 | 验收 |
|---|---|---|
| P0-15 | 异常处理 | 错误以可理解 message 展示，不暴露 Python traceback |
| P0-16 | 参数化 SQL | 所有用户输入用参数化查询 |

## 3. P1 功能清单（P0 全部通过后决定）

- **报名列表参考**（管理端调度页）：能看到该班次的报名意向作为候选参考，非强制流程。
- 技能筛选、CSV 导入导出。

## 4. 本阶段（阶段一）明确不做

- 技能自动匹配推荐、排班推荐算法
- 数据可视化大屏 / 运营驾驶舱
- 请假 / 换班
- 消息通知
- 人脸识别或定位（GPS）签到
- 复杂 RBAC

> 以上除"推荐算法、驾驶舱"外，属于**长期不做**；推荐算法与驾驶舱为**阶段二·比赛深化**内容（见第 6 节），本期不开发。

## 5. 页面总清单

### 管理端（6 页）

| 页面 | 路径（建议） | 说明 |
|---|---|---|
| 登录 | /pages/login | 双端复用，按 role 跳转 |
| Dashboard | /pages/dashboard | 统计卡片（驾驶舱留在阶段二） |
| 志愿者管理 | /pages/volunteers | CRUD + 停用 |
| 赛事/岗位管理 | /pages/events | 赛事含岗位 |
| 班次管理 | /pages/shifts | 时间、人数校验 |
| 调度 | /pages/schedule | 分配 + 报名候选参考 + 错误提示 |

### 志愿者端（3 页 + 复用登录页）

| 页面 | 路径（建议） | 说明 |
|---|---|---|
| 我的班次 | /pages/volunteer/my-schedule | 已分配班次；当天班次显示"签到"按钮，签到后变"签退" |
| 可报名班次 | /pages/volunteer/positions | 未来且有名额的班次 + "报名"按钮，报名后变"已报名，待安排" |
| 我的志愿时长 | /pages/volunteer/my-hours | 累计时长卡片 + 已完成班次明细 |

> 小程序原生不支持运行时动态改 tabBar：**不用 tabBar**，登录后 `wx.reLaunch` 跳转对应端首页，内部用普通导航跳转。

## 6. 阶段二·比赛深化（本期不开发，仅作规划与答辩叙事）

| 方向 | 内容 | 验收要点 |
|---|---|---|
| 方向2 排班推荐算法 | 调度页候选列表按匹配度打分排序（技能40/履约30/均衡20/可用10），**最终仍由管理员点击确认** | 四项打分可当场讲清，非黑盒；"人在回路"呼应自动化决策透明 |
| 方向3 可视化运营驾驶舱 | Dashboard 升级：缺口排行、技能分布、时段覆盖率、出勤/爽约趋势（wx-charts） | 四个图表均基于真实聚合数据，无写死数字 |

> 纪律：阶段二内容不进入本期 P0/P1，避免范围失控。答辩材料可提前讲叙事，但不提前开发。

## 7. 验收标准（任意成员 1 分钟说明一致）

> "组委会用管理端小程序维护志愿者/赛事/岗位/班次并完成调度，系统阻止重复、时间冲突、超员；志愿者用同一小程序登录后可看我的班次、报名岗位、签到签退、看志愿时长。本期不做推荐算法和驾驶舱，也不做通知、地图、人脸。"
